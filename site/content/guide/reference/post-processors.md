A CamCraft post is a plain JavaScript file with the `.cps` extension.
The engine evaluates it once, then calls its hooks for each input record.
There are no imports, filesystem calls, or controller connections.
Use this reference to inspect a post loaded through **Load post (.cps)**.

This page describes CamCraft's own format. Its sources are
`assets/posts/AGENTS.md`, `docs/CNC-INTERMEDIATE.md`, and
`crates/post/src/post/`. The code defines the current behavior.

## Manifest

Set manifest values at the top level, before the hooks. Boolean capability
flags must be `true`. Set it only after the post implements and
tests that behavior. A declaration does not implement controller support.

| Property | Value and purpose |
|---|---|
| `description` | Human-readable post name, also used in refusals. |
| `vendor` | Author or supplier text. New project posts use `"Camcraft"`. |
| `legal` | Legal or provenance text. |
| `certificationLevel` | Descriptive compatibility metadata; it does not certify machine safety. |
| `minimumRevision` | Descriptive revision metadata; it does not select engine semantics. |
| `extension` | Output suffix, such as `"nc"`, for filenames generated by the app. The standalone CLI uses its explicit output path. |
| `setCodePage` | Compatibility metadata assignment used by existing posts; it does not configure an output encoder. |
| `capabilities` | Numeric mask: 1 for milling, 2 for turning. The app uses it to judge which spindle the post drives. |
| `serves` | Machine kind string or array: `mill`, `lathe`, `mill-turn`, `plasma`, `wire_edm`, `sinker_edm`, `waterjet`. Built-ins also have a registry identity. |
| `programUnits` | Supported program units, normally `"mm inch"` or `"mm"`. An inch request requires `inch`. |
| `endUnits` | Unit words, such as `"G20 G21"` or `"G700 G710"`; `"note"` supports a note instead. Required for the EndUnits option. |
| `coolantModes` | Reads `Coolant` and writes the selected machine coolant code. Without it, non-flood requests refuse. |
| `afterModes` | Implements `AfterOperation`, including requested stops or home moves and setup-change stops. |
| `liveTooling` | Implements radial live-tool work with spindle C angles. |
| `axisInversion` | Implements the engine's mirrored X/Y stream, including arc and compensation changes. Also required for WCS flips. |
| `probeAxisInversion` | Implements verified probing on mirrored machine axes. |
| `threadHands` | Reads `SpindleDirection` and writes the spindle direction needed for the thread hand. |
| `workOffsetIndex` | Receives `WorkOffset` as a 1-based number. Without it, offsets 1–6 arrive as `G54`–`G59`. |
| `workOffsetMax` | Highest supported offset number; default 6. A valid declaration is a whole number from 1 to 255. |
| `continuousThreading` | Implements chip-break dips as one synchronized chain. The controller manual must support synchronization across consecutive blocks. |
| `rotariesBeforeTraverse` | `true` says the script turns the rotary axes to each section's pose at the safe Z before the first X/Y traverse. The first-traverse check then reads the work at the operation's own pose. Without it, the check reads every pose that the previous program can leave. A user's own script that declares it gets a note on the path. |
| `uprightReturn` | `true` says the script retracts to a safe height and turns the rotary axes to zero at the start of each section that follows a tilted section, before its first X/Y traverse. Without it, the engine refuses by name a section that starts with no stated angle after a section that left a rotary axis off zero. |
| `lineEnding` | `"lf"` (the default) or `"crlf"`: the end of each program line. The engine reads it after `onClose`, so `onOpen` can set it from a declared option. Other values are refused by name. |
| `linearizeArcs` | `true` writes each arc record as straight chords through `onLinear`, for a control without G2/G3. The chord sagitta is `chordTolerance` (mm, 0.01 when unstated). The engine reads both after `onOpen`; a `chordTolerance` that is not a positive number is refused by name. |
| `explains` | `"paren"` or `"semi"`. The post must append `explain(...)` to its blocks. |
| `commentMax` | Maximum explanation comment length, delimiters included; default 60. It must be a whole number from 8 to 255 when Explain is on. |
| `explainWords` | Optional dialect meanings: text, `""` to omit a meaning, or `{said: "...", takes: "S"}` to include a value word. |
| `explainTool` | `"station-offset"` for lathe tool words such as T0101; otherwise use the shared tool interpretation. |
| `declaredOptions` | Typed options shown by the host and accepted through CLI, MCP, and scripts. See below. |
| `wireEdm` | Implements wire sections, including their EDM condition. |
| `floatingTapping` | Implements explicitly requested floating-holder tapping. It does not change rigid tapping into floating tapping. |
| `fineBoring` | Implements a fine-boring cycle with its measured lateral shift. |
| `millSpindleReverse` | Implements M04 for a left-hand-cut milling tool. |
| `wcsRotation` | Implements control-side WCS rotation. The machine must also state coordinate rotation support. |
| `toolChangeMacros` | Optional `{before: "...", after: "..."}` NC strings around the first tool change and each different tool number. Repeated tool numbers still call the hook. |

Define `workOffsetName(n)` to show the controller's name for indexed
offset `n` in the UI. It is a display helper, not a motion hook.
An undeclared `serves` does not admit plasma or EDM work. On other machines,
the app also checks whether the post uses a milling or turning dialect.

Each `declaredOptions` entry has a `type` and a matching `default`.
Types are `boolean`, `integer`, `number`, `string`, and `enum`.
Optional fields are `title`, `description`, `group`, `min`, and `max`.
An enum needs nonempty `choices`: strings or `{id, title}` objects.
For example: `declaredOptions = { pauses: {type: "boolean", default: false} };`.
The post reads the resolved value as `postOptions.pauses`.
Host option names, including `Units`, `Threading`, `Smoothing`, `EndUnits`,
`Explain`, and `BetweenSetups`, are reserved.

## Hook order and arguments

Initialization loads the script, validates options and supported coordinate
transforms, then publishes `machine`, `program`, `programTools`, and
`postOptions`. It calls `onOpen()` once. Records then run in stream order.
The table describes events, rather than a requirement to call every row.
`onClose()` runs once after the last record.

| Event | Hooks and arguments |
|---|---|
| Program start | `onOpen()` |
| `PARAM` | `onParameter(name, value)`. A `SpindleSpeed` parameter then calls `onSpindleSpeed()` with no arguments. |
| `TOOL` | `onToolChange(number, name)`, inside any tool-change macros. |
| Section boundaries | `onSection()` and `onSectionEnd()`. The label is not an argument. |
| Motion | `onCommand(name)` first: `Rapid`, `Linear`, or `Circular`; then `onRapid()`, `onLinear()`, or `onCircular()`. A plunge uses `onPlunge()` if defined, otherwise `onLinear()`. |
| Cycle | `onCommand("Drilling")`, then `onCycle()`, `onCyclePoint()`, `onDwell(seconds)` for positive dwell, and `onCycleEnd()`. |
| Warning | `onComment(text)`. It remains a counted warning even if the hook emits nothing. |
| Compensation | `onRadiusCompensation(side)` where side is `left`, `right`, or `off`. |
| Thread cycle boundaries | `onThreadCycle()` and `onThreadCycleEnd()`. Explicit motion passes still follow; a native-cycle post must filter those passes itself. |
| Part handling | `onPartLoading()`, `onPartUnloading()`, `onPartTransfer()`. |
| Measurement request | `onProbe()`. This is separate from probing motion. |
| Probing motion and result | `onProbeMove()`, `onProbeRetreat()`, `onProbeGuard()`, `onProbeResult()`. |
| Plasma header and torch | `onPlasma()`, `onTorchOn()`, `onTorchOff()`. |
| Waterjet jet | `onJetOn()` and `onJetOff()`: the jet opens before the next motion record and closes after the previous one, under the section's `WATERJET` header. |
| Program end | `onClose()` |

Only literal `false` from `onCommand` filters that motion or cycle.
The engine counts filtered records and shows them in the trace.
Lifecycle hooks, including probing and torch events, bypass `onCommand`.
Most hooks can be absent, but the engine refuses missing hooks for
compensation, protected probing, or torch control when those records occur.
Other unsupported behavior must call `message()` with a clear cause.

## Input records

The `.cnc` stream starts with `; HSMW-CNC v1`. Without this header the
parser accepts the legacy `.cl` format. Geometry uses integer micrometres;
feeds use mm/min multiplied by 1000; rotary words use millidegrees.
Hooks receive millimetres, mm/min, degrees, and seconds.
The parser normalizes legacy cycle markers into program order before
assigning record indices for the trace.

| Record | Contents |
|---|---|
| `PARAM name value` | Named value; strings can contain spaces. Real values use six decimal places in the writer. |
| `WARN text` | Verification warning, counted and passed to `onComment`. |
| `TOOL number name` | 1-based library tool number and its name. |
| `SECTION label` / `ENDSECTION` | Operation boundaries. |
| `Rapid X i Y i Z i` | Absolute rapid endpoint. |
| `Feed X i Y i Z i F i` | Absolute feed endpoint and feed. |
| `Plunge X i Y i Z i F i` | Absolute plunge endpoint and feed. |
| `Arc CW` or `Arc CCW`, followed by XYZ/F and two center words | `I J` selects XY, `I K` selects XZ, `J K` selects YZ. Centers are absolute, despite the property name `IJKIncrement`. |
| Motion suffix `A i B i C i` | Commanded tool angles. These locate the tip; they do not imply pivot compensation. |
| `CYCLE TYPE X… Y… Z… R… ENTRY… Q… P… F… AT…` | Canned cycle. R is retract height, ENTRY entry height, Q peck, P dwell in milliseconds, AT the chain anchor. |
| `COMP LEFT radius [WEAR]`, `COMP RIGHT radius [WEAR]`, `COMP OFF` | Engage or cancel compensation on the next move. Without WEAR the following path is the part contour; with WEAR it is the cutter-centre path. |
| `THREAD …` / `THREAD END` | Native threading-cycle description around explicit passes. Required words are listed below. |
| `PART LOAD [ADVANCE i]`, `PART UNLOAD`, `PART TRANSFER from to` | Part handling; transfer stations are 1-based. |
| `PROBE i` | Measurement tolerance request. |
| `GUARD x y z F feed` | Stop-on-contact protected probe positioning. |
| `TOUCH x y z EXPECT x y z F feed M index` | Probe target, expected trip point, feed, and measurement index. Use `-` for no measurement. |
| `RETREAT dx dy dz EXPECT x y z F feed` | Incremental back-off from a probe trip, expected endpoint, and feed. |
| `FOUND SET n TOL tol AXIS letter expected index…` / `FOUND CONFIRM TOL tol AXIS letter expected index…` | Probe result: set offset n (0–5) or confirm only. Repeat AXIS groups for measured axes. |
| `PLASMA KERF… [CONTROL] [PIERCE…] [CUTH…] [DELAY…] [AUTOFEED] [REVERSED]` | Section kerf, heights, delay, compensation and feed mode. Unstated heights and delay belong to controller automation. |
| `TORCH ON Cid OUTER` / `INNER` / `OPEN`, optionally `PARENTid SMALLfactor` | Start a contour; SMALL is a feed factor multiplied by 1000. |
| `TORCH OFF Cid` | End the same contour. No rapid is allowed while lit. |
| `START X i Y i Z i` / `END` | Legacy position markers, consumed without a hook. |

Cycle types are `SPOT`, `DRILL`, `PECK`, `DEEP`, `TAP`, `FLOATINGTAP`,
`BORE`, `BACKBORE`, `REAM`, and `FINEBORE`. The parser also accepts joined
or separated keyed words, such as `X1000`, `X 1000`, `X:1000`, or `X=1000`.
Thread records require `X Y Z EX EY EZ MAJOR MINOR LEAD HEIGHT FIRST MIN
FINISH ANGLE SPRING PULLOUT HAND`; optional flags are `ALT 1`, `REP 1`,
and `DIP 1`. LEAD is a decimal millimetre value; ANGLE is degrees.
The other geometry words are micrometres. HAND is `right` or `left`.

## Properties available to hooks

`properties` (also `W`) contains accumulated parameters and the current
record's values. Test optional values before use. Missing rotary words are
absent, rather than zero. Subtract `OriginX/Y/Z` from absolute positions
for work-offset output. Do not subtract the origin from increments.
The engine applies declared WCS and machine-axis transforms before hooks.

| Properties | Meaning |
|---|---|
| `StartX`, `StartY`, `StartZ`; `X`, `Y`, `Z` | Point before the record and its endpoint, in mm. Cycle XYZ is center XY and bottom Z. |
| `A`, `B`, `C` | Optional commanded angles in degrees. |
| `IJKIncrement`; `CircularPlane`; `CircularDirection` | Absolute center object `{I,J}`, `{I,K}`, or `{J,K}`; plane `XY`, `XZ`, `YZ`; direction `CW` or `CCW`. |
| `FeedRate`; `FeedReference` | Feed in mm/min; optional reference `surface`. |
| `ToolNumber`, `ToolName`, `ToolDiameter`, `ToolKind`, `ToolCornerRadius` | Tool identity and geometry. Corner radius is included only when positive. |
| `SpindleSpeed`, `SpindleDirection`, `MillSpindle`, `LiveTool` | RPM; optional `reverse` spindle requests; optional `radial` live-tool work. |
| `WorkOffset`; `OriginX`, `OriginY`, `OriginZ` | Offset index or legacy G-word, and setup origin in mm. |
| `StockXYLeft`, `StockXYRight`, `StockXYFront`, `StockXYBack`, `StockZTop`, `StockTurnRadius` | Stock bounds and turning sweep radius in mm. |
| `WcsFlip`; `WcsYaw`; `WcsRotationMode` | Flipped X/Y letters; WCS yaw in degrees; rotation mode `bake` or `control`. |
| `Coolant`; `AfterOperation`; `SetupChange` | Coolant request, section-end action, and next setup name for a setup change. Unstated coolant means flood; unstated action means continue. |
| `ClearancePlane`, `RetractPlane`, `TopOfStock` | Section heights in mm. |
| `OperationName`, `OperationKind`, `SetupName`, `ToolOrientation` | Identity and commentary; lathe orientation 1–9 also defines the nose control point for applicable turning sections. |
| `command` | Motion or lifecycle event name. |
| `Advance`; `From`, `To`; `Tolerance` | Load advance in mm, transfer stations, measurement tolerance in mm. |
| `Compensation`, `CompensationRadius`, `CompensationType` | Side, radius in mm, and `control` or `wear`. |
| `CycleType`, `TappingMode` | Cycle intent; FLOATINGTAP becomes `TAP` with `floating`, while TAP uses `rigid`. |
| `R`, `EntryZ`, `Q`, `P`, `FeedRate` | Cycle retract/entry heights, peck mm, dwell seconds, feed; legacy cycle feed can be null. |
| `ChainFeedRate`, `ChainBottomZ`, `ShiftX`, `ShiftY` | Expanded-chain feed and lowest Z; fine-bore lateral shift. These can be null when unavailable. |
| `LinearMovementIncludeOpts` | `{L:[1]}` for plunges. |
| `EndX`, `EndY`, `EndZ`, `MajorDiameter`, `MinorDiameter`, `Lead`, `ThreadHeight`, `FirstDepth`, `MinimumDepth`, `FinishAllowance`, `InfeedAngle`, `SpringPasses`, `PullOut` | Thread-cycle endpoint and dimensions. Angles are degrees, lengths mm. |
| `Alternating`, `RepeatEachDepth`, `ChipBreakDips` | Thread-cycle booleans. A preceding PARAM can also name ChipBreakDips. |
| `SetWorkOffset` | Probe result destination: **0-based**, 0–5 for G54–G59; -1 sets none. This differs from WorkOffset. |
| `ExpectX`, `ExpectY`, `ExpectZ`, `Feed`, `Measure` | Probe touch's nominal trip point mm, probing feed mm/min, and measurement index (-1 for none). Probe guard also uses Feed. |
| `DeltaX`, `DeltaY`, `DeltaZ` | Probe retreat's incremental back-off mm. Its EXPECT point updates engine position. |
| `Axes` | Probe result array of `{Axis, Expected, Measures}`: axis letter, expected coordinate mm, and measurement indices. |
| `PlasmaKerf`, `PlasmaCompensation`, `PierceHeight`, `CutHeight`, `PierceDelay`, `PlasmaFeed`, `PlasmaReversed` | Kerf mm; `control`/`computer`; optional heights mm and delay seconds; `auto`/`stated`; reversed direction. Cleared at ENDSECTION. |
| `Contour`, `ContourRole`, `ParentContour`, `SmallHole` | Torch contour id, `outer`/`inner`/`open`, optional parent and feed factor. |
| `EdmCondition`, `WireSide` | Wire condition id and `die`/`punch` commentary. Wire moves describe the wire-centre path. |
| `SinkerCondition`, `ElectrodePickup`, `EdmOrbit`, `EdmOrbitRadius` | Sinker condition, pickup mm, orbit kind and radius. The current sinker post refuses an orbit. |
| `WireTaper`, `WireU`, `WireV`, `WireFourAxis` | Taper degrees, upper-guide offsets mm, or 4-axis pairing description. |
| `WireTaperDialect`, `WireCorner`, `WirePlane`, `WireAngle` | Angle-word taper: `angle`, `mitre`/`cone`, programmed plane Z, signed angle. These replace U/V where applicable. |

## Globals and prelude helpers

`currentPosition` is the `{X,Y,Z}` position before the current motion
record. `program` contains `{number, numbered, comment}`; `programNumber`
is the same number. Default number is 1; default comment is empty.
`programTools` is an array of `{number, name, diameter, kind}` for headers.
`postOptions` contains host choices and resolved declared options.
Use `postOptions.Units` (`mm` by default) for the program's unit.
For inch output, divide lengths and feeds by 25.4 and write the unit mode
before motion. `machine.units` describes the machine file's own units.

`machine` supplies name/model, `rapidRate`, `feedRateMax`, `spindleMax`,
`coolants`, `rotaries`, `rtcp`, `units`, `spindleRanges`, `rigidTapping`,
`rigidTappingStated`, and `safeRetractZ`. Machine kind and EDM facts are
included when applicable. Unknown retract height is null. Never assume
machine Z0 is safe. RTCP output requires the machine's geometric support.

| Helper | Behavior |
|---|---|
| `write(s)`, `writeOutput(s)`, `writeWord(w)` | Append to a pending line. writeWord ignores null, undefined, and empty strings. |
| `writeln(s)` | Append and flush the pending nonempty line. |
| `writeBlock(...parts)` | Flush a pending line, join nonempty parts with spaces, and emit a block. |
| `writeAddress(letter, value, dp)` | Append a letter and formatted number; ignores null/undefined values. It does not add a space. |
| `writeComment(s)` | Emit parentheses; replace embedded parentheses and control characters with spaces. |
| `writeBlankLine()`; `linesWritten()` | Emit an empty line; flush and return the output line count. |
| `getProperty(k)`; `setProperty(k,v)` | Read or change the current properties object. |
| `message(s)` | Add a warning. It emits no NC text and blocks the app's write. |
| `formatUnit(v,dp)`; `formatMotion(v)` | Fixed decimals with trailing zeros removed; default 3 decimals. Invalid numbers become `"0"`; validate first. These do not convert units. |
| `formatFeed(v)` | Round a positive finite feed to an integer; invalid or nonpositive values become `"0"`. |
| `setLanguageVersion(v)` | Accepted and ignored. |
| `explain(...words)` | Explanation comment, or empty text when Explain is off. Also accepts one array. The post must append it. |
| `rotaryRate(letter)` | Machine rotary feed limit, falling back to rapid limit, in degrees/min; 0 when unstated. |
| `rotaryFeedCap(f,lin,turns,mode,eps)` | Cap feed from linear length mm and `[degrees, degrees/min]` pairs. Mode is `composite` or `path`. |
| `rotaryFeed(p,prev,letters,mode,arc,step,org,inch)` | Return `{feed,capped}` or `{refuse:text}` for posted geometry. prev holds prior angles; step and origin describe output rounding. |
| `rotaryFeedPosted(v,inch)`; `rotaryFeedWord(v,inch)` | Read back rounded feed in mm/min; produce a conservatively rounded capped F word, or empty text below the usable minimum. |

The engine owns the output buffer `OUT`, pending `LINE`, and warning array
`MESSAGES`. Use helpers rather than changing those buffers directly.
The default `onComment` echoes text. Default part hooks write comments;
default `onProbe` writes the tolerance as a comment. These defaults do not
implement a feeder, a station transfer, or a measurement protocol.

Do not depend on time or randomness. Equal input must produce equal output.
Hooks have bounded loop, recursion, stack, and output budgets. A limit
failure is an error, not permission to publish a partial program.

## Refusals: cause and correction

The app checks the document before running a post. It also rejects any
engine warning. It leaves an existing output file unchanged on refusal.
The standalone tool has different warning behavior, described below.
Messages can include the operation, setup, machine, or post name before
the text in this table. Read those names to locate the affected setting.

| Message text or distinguishing words | Cause and correction |
|---|---|
| `no operations to post` / `every operation is suppressed` | Create an operation or include one in the program. |
| `fix the tool before posting` | Missing or unsuitable tool. Select a valid tool before generation. |
| `no toolpath yet - generate it first` | Generate the named operation. |
| `inputs moved since generation - regenerate before posting` | An input changed. Regenerate and verify the operation. |
| `post blocked -` followed by verification problems | Fix the named gouge, collision, limit, workholding, review, or setup problem. See [Reading a refusal](@/guide/reference/refusals.md). |
| Machine kind / post mismatch; `serves` | Select a post for the actual machine kind. A custom post must state the kinds it implements. |
| Program unit / `programUnits` | Select a supported program unit or a tested post for that unit. |
| `EndUnits` / `endUnits` | Remove the requested end-unit change or use a post that implements it. |
| `Explain G-code is on` | Disable Explain or implement a supported comment form. Correct an invalid commentMax or explanation table. |
| `does not declare coolantModes` | Use Flood or a post that reads the requested coolant. A missing machine coolant code also needs correction. |
| `does not declare afterModes` | Use Continue, select a suitable Between setups mode, or use a post that writes the required stop/home. |
| `does not declare liveTooling`, `threadHands`, `continuousThreading`, or `millSpindleReverse` | The post cannot express the requested spindle/thread behavior. Select a tested supporting post; do not add a flag alone. |
| `floatingTapping is not declared` / fine-boring shift or capability | Use a post that implements that cycle. For fine boring, verify the generated lateral shift. |
| `work offset … is not a work offset number` | Set an integer offset from 1 to 255, subject to the post's limit. |
| `does not declare workOffsetIndex` / `expresses work offsets 1-… only` | Select an offset the control/post supports or use a supporting post. |
| `axisInversion` / `probeAxisInversion` / inverted-axis refusal | Use a post tested for the actual axis configuration. Correct an unsupported machine axis definition. |
| `WcsRotation Control` / `wcsRotation` | Use Bake into XY or a supported controller and post. Control rotation cannot combine with inverted axes. |
| `on a rotated work offset is not supported` | Use an unrotated setup for the named probing, EDM, threading, live-tool, rotary, or non-XY-arc behavior. |
| `does not define onRadiusCompensation` | Use computer compensation or implement the control's compensation hooks and safe leads. |
| `does not define onProbeMove`, `onProbeRetreat`, `onProbeGuard`, or `onProbeResult` | Use a post with the required protected probing protocol. A plain feed is not a safe substitute. |
| `wireEdm` / `does not serve a sinker EDM` | Select the correct EDM post and supply its machine condition/code data. |
| Torch/header/contour warning | Correct the stream: one header, matching ON/OFF ids, no rapid while lit, and no lit torch at section or program end. Implement both torch hooks. |
| `post blocked - … warning(s)` | Inspect every warning, including stream WARN and script message calls. Correct the cause and post again. |
| `post engine:` / script error / parse error | Correct the named source line, input record, option, or machine data. |
| `post output line limit exceeded` / loop or recursion limit | Remove runaway expansion or recursion. Do not use a partial output. |

Posts can also refuse controller-specific limits: spindle speed, safe
retract, clearance, canned-cycle feed, tapping support, or EDM condition.
Use the named fact to correct the machine or operation. Keep a refusal
when the controller behavior remains unconfirmed.

## Run a post by itself

From a source checkout, build only the standalone tool:

```sh
cargo build -p camcraft-post --bin post
target/debug/post --trace trace.txt --log warnings.txt --units mm example.cps example.cnc example.nc
```

Installed builds can invoke `post` directly (`post.exe` on Windows).
Add `--machine path/to/machine.mch` to provide machine facts.
Add repeatable `--option key=value` for declared options; the tool validates
the key, type, and range. `--units` accepts only `mm` or `inch`.
The three positional paths are always script, input stream, output program.

Read `example.nc`, the warning list, and `trace.txt`. A trace block names
the input record and the lines it produced. A filtered record says
`(no output)`; header and end blocks have no record index.
JavaScript diagnostics identify `user.cps` with 1-based source positions.

**This tool does not run the document verification gate.** It writes
output and returns success even when the engine reports warnings.
Warnings go to stderr, or to `--log` when supplied. A log is written only
when warnings exist, so an old log can be stale; use fresh paths for each
run. Parse, script, option, and file errors return failure.
Do not send this debugging output to a machine as a verified program.

## Small complete example

This post produces a text trace, not runnable G-code. It deliberately
refuses other motion kinds so that an unsupported record stays visible.
Save it as `example.cps`:

```javascript
// Provenance: original example of the CamCraft hook contract.
description = "Example trace";
extension = "txt";
serves = ["mill"];
programUnits = "mm";
function onOpen() { writeComment("EXAMPLE ONLY"); }
function onCommand(name) {
  if (name !== "Rapid" && name !== "Linear") {
    message("Example trace does not support " + name);
    return false;
  }
}
function point(kind) {
  writeBlock(kind, "X" + formatUnit(properties.X),
    "Y" + formatUnit(properties.Y), "Z" + formatUnit(properties.Z));
}
function onRapid() { point("RAPID"); }
function onLinear() { point("FEED"); }
function onClose() { writeComment("END EXAMPLE"); }
```

Save this as `example.cnc` and run the command above:

```text
; HSMW-CNC v1
SECTION Example
Rapid X 1000 Y 2000 Z 5000
Feed X 3000 Y 2000 Z 5000 F 100000
ENDSECTION
```

The output is exactly these four lines, each ending with a newline:

```text
(EXAMPLE ONLY)
RAPID X1 Y2 Z5
FEED X3 Y2 Z5
(END EXAMPLE)
```
