# CamCraft MCP Agent Guide

CamCraft exposes a Model Context Protocol (MCP) server on stdio (`camcraft-cli mcp`, #128), allowing an AI agent to drive a complete CAM programming session headlessly: importing models, defining setups and stock, selecting tools, creating and editing operations, selecting geometric features, simulating/verifying, and posting NC programs.

## Architecture & Principles

- **Transport & Protocol:** Standard JSON-RPC 2.0 over newline-delimited stdio (`initialize`, `tools/list`, `tools/call`, `ping`).
- **Everything Is a Command:** The MCP server owns one headless document (`crates/app/src/script/mod.rs:Env`) and one command `History`. Every mutation is dispatched through a concrete undoable command (`env.history.execute`), guaranteeing that `undo` and `redo` work headlessly with the exact same invariants as the GUI.
- **Refusals as Data & Prime Directive:** All tool failures return structured refusals: `{ isError: true, content: [{ "type": "text", "text": "<tool_name>: <reason>" }] }` naming the exact parameter or physical constraint violated. In accordance with CamCraft's Prime Directive (no panics in user-triggered code; crashes are bugs), systems and commands return explicit `Result`/`Option` errors. The `catch_unwind` wrapper in `crates/app/src/mcp/mod.rs` serves strictly as a cold, last-resort crash barrier to prevent an unexpected internal engine defect from dropping the stdio connection.

## Standard Agent Workflow

```
       1. Import / Open
   (import_model / open_project)
              │
              ▼
    2. Stock, Setup & WCS
 (set_stock, add_setup, set_wcs,
  set_wcs_from_features, set_wcs_flip,
  set_work_offset, load_machine)
              │
              ▼
         3. Fixtures
 (add_fixture, move_fixture)
              │
              ▼
          4. Tooling
 (add_tool, import_tool_library)
              │
              ▼
   5. Operations & Geometry
 (add_operation, list_features,
  set_operation_geometry, edit_operation)
              │
              ▼
         6. Generate
         (generate)
              │
              ▼
     7. Verify & Inspect
 (verify, get_fixture_findings,
         render_stock)
              │
              ▼
          8. Post
          (post)
```

## Tool Reference

The authoritative registry is `crates/app/src/mcp/tools.rs:all()` or the `tools/list` protocol method.

The [generated tool reference](../../../docs/agents/mcp-tools.md) lists every tool and argument from that registry. Read it with `camcraft-cli mcp reference`. Use `camcraft-cli mcp prompt` for the compact local-model prompt. Both outputs come from `crates/app/src/mcp/catalog.rs` and the live tool table. The sections below give workflow details.

### 1. Document Lifecycle & History (`tools.rs`)
- `open_project { "path": string }`: Load an existing `.camproj` file, replacing the current document and clearing history.
- `save_project { "path"?: string }`: Save the current document to disk. Without a path, overwrites the last opened/saved file.
- `import_model { "path": string, "name"?: string, "facet_budget"?: integer }`: Import a mesh model (STEP, STL, OBJ). Re-importing with an existing name updates that model. `facet_budget` sets the maximum STEP triangle count (new-import default 30000000); raise it to import a large model at full detail. Omitting it on re-import keeps the recorded budget. A budget outside the schema's limits or given for an STL/OBJ file is refused by name. One undo step. A non-default budget appears in the reply and in `get_job`'s `models[].facet_budget`.
- `delete_model { "name": string }`: Delete an imported part through `DeleteEntity`, one undo step; undo restores its geometry, placement and import fidelity. Refuses by name without changing the document or history: an unknown name, a non-model, a fixture (remove its fixture binding first with `remove_fixture`), a model used as an operation source, feature selection or area boundary, or a model used by any setup stock made with `from_model`. The refusal names the dependent operation or stock; change that reference first. Returns `{ deleted }`.
- `move_model { "name": string, "position": [x, y, z], "rotation"?: [x, y, z, w] }`: Place and turn an imported part (mm, unit quaternion; omitted rotation keeps the current one). Undoable; reports where stock that follows the part ended up (#716).
- `repair_model { "name": string, "weld_tol"?: number, "max_hole_edges"?: integer }`: Weld vertices (default 0.001 mm), drop degenerate or duplicate triangles and fill open loops of at most `max_hole_edges` edges (default 256); reports the counts (#717).
- `import_dxf { "path": string, "setup"?: string, "units"?: "mm" | "in", "join_tol"?: number, "name"?: string }`: Place a DXF drawing as a profile on the top face of a setup's stock, at the stock origin (the active setup by default). A profile is reference geometry for cutting, not a model: make the stock first (`set_stock`); the setup needs no model. `units` wins over the file's `$INSUNITS`; a file that states no unit is refused by name until `units` is given. The reply states the units used, the layers, the closed, open and rejected chains, and the skipped entities by kind. Undoable (#1862).
- `move_dxf_profile { "name": string, "position": [x, y], "angle"?: number }`: Move a placed profile on its stock face (mm from the stock origin, degrees about the face normal; an omitted angle keeps the current one). A profile has no Z and no tilt. Undoable (#1862).
- `insert_text { "text": string, "height": number, "position"?: [x, y], "angle"?: number, "letter_spacing"?: number, "setup"?: string, "name"?: string }`: Place a typed string as a profile of single-line engraving strokes on the stock top. The strokes are tool-centreline paths in mm on the layer "text". The font has capital letters, digits, the space and - _ . : / # + = ( ). `height` is the cap height in mm (0.5 to 1000). `position` [x, y] is the baseline start in mm from the stock origin (default [0, 0]). `angle` turns the baseline about the face normal in degrees counterclockwise (default 0). `letter_spacing` adds a gap between characters in mm (default 0). `move_dxf_profile` moves it, and `get_job` lists it under "profiles". Undoable (#2679). Refused by name: an empty text, a character with no glyph (a lower-case letter is not changed to a capital), a height or spacing outside the limits, a placement that is not finite, a setup with no stock, an unknown setup, a name in use.
- `set_model_link { "model": string, "path": string | null }`: Link a model to a file, or unlink it (`path: null`), as the Browser's Unlink does (#2463). An import from a file links the model already; linking records the file's SHA-256 now and does not import it. In the app window, a linked model whose file gets a new SHA-256 is imported again under the same name: one undo step, and its operations go Stale. Nothing regenerates or posts by itself. One undo step. Returns `{ model, source: {path, sha256} | null }`; `get_job`'s `models[].source` shows the link. Refused by name: an unknown model, a name that is not a model, a file that cannot be read, unlinking a model that is not linked.
- `get_job {}`: Dump the entire document state (setups (each with `model_reference`: a solid part, or the `virtual` reference of its placed DXF profiles), stock, WCS, models, DXF `profiles`, tools (each row with its own `number`, or `null`, and the `posts_as` T number), operations, status), and each setup's `workholding_max_rpm` (its stated limit, or `null`). Top-level `units` is `"mm"` or `"inch"`; `machine` contains `path` and `definition` (both `null` when no document machine is mounted). Each setup's `post` is its own post name or path (`null`: follows the document); `posts_with` names its resolved post.
- `set_units { "unit": "mm" | "inch" }` (`units_tools.rs`, #902): Set the document's display and posted-program unit (G21/G20 or the dialect's word). Stored geometry and parameters stay unchanged in mm; MCP dimensions remain in mm. One undo step through `SetUnits`; `undo` restores the previous unit and `redo` reapplies it. Returns `{ unit }`; `get_job.units` reports the same choice. Refused by name: a missing or invalid unit, or the unit the document already has. A post that cannot write inches refuses an inch document when posting.
- `undo {}`: Undo the last mutating document command.
- `redo {}`: Redo the last undone command.

### 2. Setups & Kinematics (`setup_tools.rs`, #181)
- `add_setup { "name": string, "datum_from"?: string }`: Declare a new setup and activate it. Can copy stock/WCS from an existing setup.
- `activate_setup { "name": string }`: Switch the active setup context for subsequent operations and edits.
- `set_operation_setup { "operation": string, "setup": string | null }`: Move an operation into another declared setup (`null`: the implicit first position), as the GUI's setup move does (#731). The stamp is kept, so the answer's `status` reads `ok` or `stale` by the staleness law; the moved operation joins the target's unranked tail. One undo step. Refused by name: an unknown operation or setup, a move to where it already is.
- `delete_setup { "name": string }`: Delete a declared setup with its private stock and WCS (#731); one undo restores them. Refused by name: an unknown setup, an operation or program entry still machining in it (`move or delete it first` - use `set_operation_setup`), a setup another is placed relative to.
- `set_wcs { "origin"?: [x, y, z], "stock_point"?: string, "offset"?: [dx, dy, dz], "rotation"?: [qx, qy, qz, qw] }`: Place the active setup's WCS origin and orientation quaternion.
- `set_wcs_circle_centre { "edge": { "model": string, "id": "chain:0x…" }, "rotation"?: [qx, qy, qz, qw] }`: Place the active setup's WCS origin on the centre of a picked circular edge (a hole rim or boss edge, full circle or arc), at the edge's height; returns the circle's centre, axis and diameter. Refuses a straight edge, a non-circular curve, a face or a vertex by name (#739).
- `set_wcs_from_features { "picks": [{ "model": string, "id": string, "role": "origin" | "x" | "y" | "z" }], "setup"?: string }`: Place the active setup's WCS on a frame fitted to `list_features` picks - the GUI's "Set WCS from features" law (#701, #937). Axes read in Z, X, Y priority: the first axis pick is exact, the second squared to it, the third derived right-handed. A flat face sets its outward normal, a straight edge its direction, a curved wall (face or patch) its fitted axis; the origin is a vertex, a face's centroid or a wall's centre (else the second axis pick's anchor), projected onto the first pick's plane when that is a face. One undo step. Refused by name: under two picks, a role given twice, under two axes, a pick that cannot set its role, near-parallel axes (< 5 deg), a stale id, a `setup` that is not the active one. Note: a `list_features` face row's `normal` and `facing` are the outward side (#956). Where the outside cannot be told (an open or inside-out shell) both are null and `outside_unknown` holds the reason (#2186); tell such faces apart by `bounds`, or repair the mesh.
- `set_wcs_flip { "x"?: bool, "y"?: bool, "z"?: bool, "setup"?: string }`: Set which axes of a setup's WCS run reversed (a flip: X+ becomes X-), as the WCS page's Flip X / Flip Y / Flip Z buttons do (#1720). An axis not given keeps its flag; the origin and rotation do not change. One undo step. Returns `{ setup, label, flip: {x, y, z}, refused }`. Toolpaths do not change. The post mirrors the program on a flipped X or Y: coordinate signs, arc direction (`G2`/`G3`) and cutter compensation side (`G41`/`G42`) (#1649). `refused` is `null` when the flip is carried. Else it holds why the post refuses it: a flipped Z, a WCS that is also rotated, a post not verified for a mirrored program (Fanuc and Haas are), or an operation of the setup that does not post in a flipped WCS (probing, turning, rotary, multi-axis, 3+2 tilted, wire or sinker EDM), with the operation names. `get_job`'s `setups[].wcs.flip` shows the flags. Refused by name: no flag given, a flag that is not a boolean, an unknown setup.
- `set_work_offset { "index": integer | "G54".."G59" | null, "word"?: (alias of index), "setup"?: string }`: Set the work offset a declared setup posts at (#931). `index` is 1-based, up to the maximum of the setup's own post (6 on most posts, 9 on Tormach PathPilot); the words `G54`–`G59` are accepted as aliases of 1–6, and `word` is the older spelling of the same argument (give one, or both agreeing). An offset the setup's post cannot express is refused by setup name (e.g. `setup Setup1 uses work offset 7, but its post ... expresses work offsets 1-6 only`). `null` clears it (offset 1). Returns `{ setup, index, name, word, label }`: `name` is what the post calls the offset (e.g. `G55`, `G59.1`, or `work offset 9` when the post gives none); `word` is kept as an alias of `name`. `get_job`'s `setups[].wcs` and `set_wcs` carry the same `index` / `name` / `word`.
- `load_machine { "builtin"?: string, "path"?: string, "clear"?: boolean, "setup"?: string }`: Mount a machine configuration at document or setup level: a built-in preset by name (`"VMC 3-axis"`, `"Lathe"`, `"Mill-turn"`, the Tormach models, ...) or a `.mch` file by path; `clear: true` mounts none. "Mill-turn" (`millturn.mch`, model `MULTITASKING 5-AXIS`, kind `mill-turn`) is a lathe with live tooling on a C axis: it turns on the work spindle and mills with driven tools. It is not turning on a mill (the part in a mill spindle, lathe tools on the table, one work offset for each tool, e.g. Tormach RapidTurn): no preset or machine kind supports that yet (#2580). When a user says "mill-turn", confirm which of the two they mean before you mount a machine.
- `set_workholding_max_rpm { "max_rpm": number | null, "setup"?: string }`: State the rated maximum rpm of a setup's chuck or collet; `null` clears it. Refused with a named error: a missing or non-numeric value, zero, negative or non-finite numbers, anything under 1 rpm or over 100000 rpm, an unknown setup, and a value the setup already states. `setup` defaults to the active one. One undo step. At post time, a constant-rpm (G97) turning operation faster than the limit is refused by name, and a constant-surface-speed (G96) section's rpm ceiling is capped at it (Fanuc `G50 S`, Tormach `G96 D`).
- `edit_machine { "patch": object, "setup"?: string }`: Edit the mounted machine's definition with a JSON merge patch (RFC 7396: an object merges, `null` removes a key, any other value replaces), e.g. `{"edm": {"max_orbit_radius": 0.5}}`. Keys are those `get_job`'s `machine.definition` shows. Applies as one undo step, like the Machine window's Apply. Refused by name, changing nothing: a `patch` that is not an object, an unknown key, an insane value, no machine mounted (`load_machine` first), an unknown setup, or a `setup` that follows the document's machine (edit that one, or give the setup its own first). Without `setup`, edits the document's machine.
- `get_rotary_stack { "setup"?: string }`: Read the active setup by default. Returns `setup`, `stated_nose_to_axis` (mm or `null`), `machine_rotaries` (the machine's work-turning rotaries, each with `rotary` and `nose_to_axis`), `stack` and `refused`. Without a stated figure, `stack` describes the tallest rotary-subplate stack: total `thickness` and `layers` top down, each with `fixture` and `thickness` in mm. The rise includes every plate under that subplate and any higher support read from its height over the machine table. `stack` is `null` with a stated figure, no stack, or a refusal. `refused` names why the rise cannot be judged, such as an imported plate with no stated thickness; otherwise it is `null`.
- `set_setup_nose_to_axis { "setup": string, "nose_to_axis": number | null }`: State a setup's spindle-nose-to-rotary-centreline figure in mm, measured on the stack the rotary stands on; it wins over the machine file's figure less the stack. Both arguments are required; `setup` does not default to the active setup. `null` clears the stated figure. One undo step through `SetSetupNoseToAxis`; `undo` restores the previous figure and `redo` reapplies the change. Returns the same fields as `get_rotary_stack`. Refused by name: an unknown setup, a missing or non-numeric figure, a non-finite value, a value at or below zero or above 5000 mm, or an unchanged figure.
- `set_setup_post { "post": string | null, "setup"?: string }`: Give a declared setup its own post: a built-in post name or a `.cps` path. `null` clears it, so the setup follows the document's post again. Sets the field only; posting judges whether the post serves the setup's machine. One undo step.

### 3. Fixtures & Workholding (`fixture_tools.rs`, #181)
- `add_fixture { "model": string, "setup"?: string }`: Tag an imported model as fixture steel for collision checking.
- `remove_fixture { "name": string }`: Unmark a fixture model.
- `move_fixture { "name": string, "position": [x, y, z], "rotation"?: [qx, qy, qz, qw] }`: Position a fixture body in world coordinates.
- `turn_fixture { "name": string, "axis": "x" | "y" | "z", "degrees": number }` (`fixture_turn_tools.rs`, #2174): Turn a fixture about a world axis through its own origin (90 or -90 is a quarter turn, exact). Plate riders turn with it; a part or stock it held stays and is named in `warning`. A turn that changes nothing is refused. One undo step.
- `get_fixture_findings {}`: Query live collision checks between generated toolpaths and fixture solids / machine table.
- `locate_part { "part": string, "fixture": string, "mates"?: [{ "part", "fixture" }] (1 to 3), "offset"?: [dx, dy, dz], "turn"?: number, "move"?: "part" | "fixture" }`: Locate the part in a fixture by mates: each mate pairs a part face or vertex id with the fixture face or vertex it sits on (ids from `list_features`), in order: floor, fixed jaw, stop (3-2-1). Then an optional `offset` (mm) and `turn` (degrees about the first face mate's normal). `move: "fixture"` moves the fixture on the part instead (default `"part"`). One undo step; refusals and an interpenetration warning are named.
- `add_builtin_vise { "size": string, "setup"?: string, "fit_to_stock"?: boolean, "position"?: [x, y, z], "rotation"?: [x, y, z, w], "opening"?: number, "dimensions"?: object }`: Place a built-in generic milling vise as a fixture of a setup (the active one by default). `size` is a row of the size table (the `enum` in the tool's schema). `fit_to_stock: true` sets it against the setup's stock and opens the jaws to it, ignoring `position`, `rotation` and `opening`. Otherwise it goes at `position` and `rotation` (default the origin), with `opening` in mm (default half the maximum). `dimensions` overrides figures in mm.
- `set_vise { "name": string, "opening"?: number, "from_stock"?: boolean, "dimensions"?: object }`: Change a placed built-in vise: its jaw opening in mm, or `from_stock: true` to open the jaws to the setup's stock as the vise stands, and/or dimension overrides in mm. The mesh is regenerated; one undo step.
- `add_accessory { "kind": string, "setup"?: string, "position"?: [x, y, z], "rotation"?: [x, y, z, w], "under_stock_in_vise"?: string, "above"?: number, "fit_to_stock"?: boolean, "grip"?: "outside" | "inside", "steps"?: integer, "dimensions"?: object }`: Place a built-in workholding accessory as a fixture of a setup. `kind` is one of `parallels`, `block`, `step_block`, `strap_clamp`, `soft_jaw`, `rotary_subplate`, `three_jaw_chuck`, `four_jaw_chuck` or `collet_chuck` (the schema's enum). The three chuck kinds are lathe chucks: the frame's z = 0 is the face the work stands on, +Z the spindle axis out of it, the body below; a chuck turns with the part, so the lathe holder check reads it as steel and a holder in its jaws blocks the post. `fit_to_stock: true` (chucks only) closes the chuck on the setup's round stock standing on a vertical axis, ignoring `position`, `rotation` and the grip diameter or collet bore: the face goes to the stock's underside (stepped jaws: the stock sits on the step; a collet takes the stock its nose length deep). It is refused by name without stock, on stock that is not round, and for an inside grip. `grip` (jaw chucks only, default `outside`) is `inside` when the jaws open into the work's bore: `grip_diameter` is then that bore and `jaw_length` runs inward from it. The dimensions `step_height` and `step_depth` (jaw chucks; both 0 for plain jaws) make stepped jaws: the step the work sits on, its height over the face and its radial reach under the work. `under_stock_in_vise` (parallels only) names a built-in vise fixture and fits the parallels under the stock in it, ignoring `position`, `rotation` and the height; `above` (default 6.35 mm) is how far the stock's top stands over the jaws. `steps` is the step count of a `step_block`. A `rotary_subplate` goes on a fixture plate's dowel pair with `place_on_plate`.
- `set_accessory { "name": string, "steps"?: integer, "grip"?: "outside" | "inside", "dimensions"?: object }`: Resize a placed built-in accessory: dimension overrides in mm (`steps` for a step block, `grip` for a jaw chuck). For a `rotary_subplate`, both this tool and `add_accessory` accept `length`, `width`, `thickness`, `bore_spacing`, `bore_x`, `bore_y` and `bore_diameter` in `dimensions`. The subplate's origin is the first pin bore at its underside; +X points toward the second bore. Refused by name if a mounted subplate's resized pins no longer fit the dowel pair or its footprint hangs off the plate. The mesh is regenerated. One undo step.
- `add_fixture_plate { "preset": string, "setup"?: string, "on_table"?: boolean, "position"?: [x, y, z], "rotation"?: [x, y, z, w], "dimensions"?: object, "thread"?: string, "dowels"?: object | null, "counterbore"?: object | null }`: Place a built-in generic grid (tooling) plate as a fixture of a setup. Its frame's origin is the plate's corner on its top face (x along the length, y along the width, the slab below). `on_table: true` centres it on the setup machine's table, lying on its top, and ignores `position` and `rotation`. `dimensions` overrides the preset's figures in mm (`offset_x` and `offset_y` place A1 from the origin corner); `dowels` is `{pitch_x, pitch_y, offset_x, offset_y, diameter}` or `null`; `counterbore` is `{diameter, depth}` or `null`. Grid locations: rows lettered along +Y from A, columns numbered along +X from 1. One undo step; nonsense figures are refused by name.
- `set_fixture_plate { "name": string, "dimensions"?: object, "thread"?: string, "dowels"?: object | null, "counterbore"?: object | null }`: Change a placed built-in plate's figures, in the same shapes as `add_fixture_plate`. The mesh is regenerated and every fixture on it is re-placed at its named location. Refused if a location is gone, a fixture would hang off the plate, or a mod vise jaw would reach into the stock. The reply's `warning` names a re-placed fixture, or a new slab sitting in a part or the stock. One undo step.
- `detect_plate_grid { "name": string, "clear"?: boolean }`: Make an imported fixture a plate by detecting its hole grid: holes on its Z, an axis-aligned lattice, each hole snapped to its node within 0.05 mm, read in the model's own frame. Refused by name when its holes form no regular grid, or when the plate is turned in its model. `clear: true` stops it being a plate. One undo step.
- `get_plate_grid { "name": string }`: Read a plate's grid: pitch, rows and columns, the location names, gaps, the dowel lattice, and the fixtures standing on it.
- `place_on_plate { "fixture": string, "plate": string, "hole"?: string, "dowels"?: [string, string], "yaw"?: number }`: Place a fixture on a plate, either at one grid location (`hole`, e.g. `"C3"`: its origin on the hole at the plate top) or on a dowel pair (`dowels`: origin on the first location, +X toward the second). `yaw` (degrees, default 0) turns it about the plate's Z. The placement is remembered, so moving the plate moves it. A rotary subplate goes only on a dowel pair whose spacing matches its `bore_spacing` within 0.05 mm, never at a single hole. Refused by name: an unknown location, a fixture that would hang off the plate, subplate pins that do not fit. One undo step.
- `add_mod_vise_pair { "plate": string, "hole": string, "size": string, "yaw"?: 0 | 90 | 180 | 270, "insert"?: "hard" | "soft", "fixed"?: object, "adjustable"?: object }`: Place a modular plate-mounted vise: two jaw blocks bolted to grid holes. The fixed block goes on `hole` (its anchor bolt), turned `yaw` degrees (default 0: its jaw faces +Y). The adjustable block, turned half a turn, goes on the same grid line at the hole nearest the setup's stock that leaves it clear, then slides along its slots until its jaw touches the stock. `size` is the preset pair; `fixed` and `adjustable` override block figures in mm. Refused by name: stock out of the slots' reach, a block off the plate, a plate with no grid, no stock, or stock in the fixed jaw or beside the jaws. One undo step.
- `set_mod_jaw { "name": string, "figures"?: object, "insert"?: "hard" | "soft" }`: Change a placed mod vise jaw block's figures or its jaw insert. `figures` takes block figures in mm, `slide` (an adjustable block's travel along its slots), `bolts` and `pins` as `[x, y]` points in the block frame. The block stays on its hole and turn. Refused by name: not a jaw block, a figure that breaks the block law, a bolt or pin off the grid, the block hanging off its plate, or its jaw face pushed into the stock. A jaw lifted off the stock comes back as `warning`. One undo step.
- `refit_mod_vise { "adjustable": string, "fixed"?: string }`: Re-fit a mod vise pair's adjustable block to the setup's stock as it stands now, after the stock changed: the fixed block stays, the adjustable block moves to the hole nearest the stock that clears it and slides until its jaw touches the stock. `fixed` names the fixed block when its plate carries more than one. Refused by name, with nothing moved: stock out of the slots' reach, stock in the fixed jaw or beside the jaws, no stock. One undo step.

### 4. Stock & Tool Management (`tools.rs`, `edit.rs`, `body_tools.rs`, #355, #361)
- `set_stock { "box"?: { "dx", "dy", "dz" }, "cylinder"?: { "diameter", "height" }, "from_model"?: string, "axis"?: "z" | "x" | "y", "angles_deg"?: { "yaw"?, "pitch"?, "roll"? } }`: Define setup stock as a box in mm (centred in XY, z from 0 to `dz`), a cylinder, or a copy of a model's mesh. `axis` lays the cylinder axis (or the box height) along X or Y; `angles_deg` gives a custom turn instead (not both). One undo step through `SetStock`; returns `{ stock, axis, angles_deg }`. The simulation refuses a cylinder laid along X or Y and a stock tilted off the axes, by name (#2576).
- `fit_stock { "shape"?: "box" | "cylinder", "margin"?: number, "sides"?: [number, number, number, number, number, number] }`: Fit the active setup's stock to its parts, never fixtures (including vises, accessories and plates). `shape` defaults to `"box"`; `"cylinder"` fits a Z cylinder snug about the parts. `margin` is the allowance on every side in mm (default 2). `sides` gives six allowances in mm, ordered [-X, +X, -Y, +Y, -Z, +Z], and replaces `margin` (box only). Keeps the stock's rotation. One undo step through `SetStock`; returns `{ stock }`. Refused by name: no models, only fixtures, negative or non-finite allowances, malformed parameters (including a `sides` array without six finite numbers), an unknown shape, `sides` with a cylinder, or models with no usable extent (#1538).
- `set_raw_stock_only { "on": boolean }`: For a stock made from a model (`set_stock` `from_model`), say whether that source model is raw stock only - a casting or blank you cut into, not the finished part. Default off: the model is judged like every model. On: the gouge verdict leaves it out. One undo step. Refused by name when there is no stock yet ("set the stock first"), when the stock is not made from a model, or when the source model has no geometry. The mark holds only while the model is still the stock's source and its geometry and placement (position and rotation) are unchanged, so moving or turning the model voids it; otherwise it is ignored and the post says so by name. An operation that machines the model (as its source or in a boundary pick) puts it back in the verdict. If the mark leaves nothing to judge, the post is refused by name.
- `list_tool_catalog {}`: List built-in tool definitions.
- `add_tool { "catalog"?: string, "definition"?: object, "name"?: string }`: Add a tool: a copy of a `list_tool_catalog` entry, or a full definition (`get_job`'s tool shape); `name` defaults to the catalog name. Assigns the lowest unused tool number in 1-99999 that the mounted machine does not reserve (a probe takes the machine's reserved probe pocket; a cutter on a reserved number or name is refused) and returns `number` and `posts_as`. In `add_tool` and `edit_tool` definitions, `cutting_data` rows accept `"material": "unknown"` (the tool's default row, alongside workpiece material words) and optional `stepdown` / `stepover` in mm (`feed` in mm/min); duplicate materials, non-positive or non-finite values, or `stepover` wider than the cutter are refused by name. A form mill (`kind: "form_mill"`, #3369) states `form`: a `preset` (`kind` `roundover`, `cove`, `ogee`, `v_groove` or `bead`, with its numbers) or drawn `points` `[z, r, arc]`, and `pilot_len`. The preset writes the points; the outline sets `diameter` and `flute_len`. Each operation refuses a form mill by name.
- `edit_tool { "name": string, "patch": object }` (`tool_edit.rs`, #1062): Edit a document tool by its `get_job` `tools[].name`. `patch` is a partial flat `ToolDto`, the shape of `add_tool.definition` and `get_job`'s `tools[].definition`: e.g. `{ "rpm": 4321, "vendor": "Acme" }`. Fields include `kind`, `diameter`, `flute_len`, `rpm`, `feed`, `flutes`, `cutting_data`, `part_number`, `vendor`, `coating`, `helix_deg` and `notes`. JSON merge patch keeps omitted fields and removes optional keys with `null`. Returns `{ tool, definition }` with the updated definition. Runs `ChangeTool` as one undo step; `undo` restores the previous definition and `redo` reapplies it. Operations using changed tool geometry become stale. Refused with a named reason: an unknown or non-tool name, a non-object patch, an unknown field, invalid tool dimensions, catalog values or cutting-data rows, a retype incompatible with an operation, or a change that no longer fits its holder body or drawn cutter. `number`, `body` and `cutter` keys are refused; use `set_tool_number`, the tool-body tools and `set_tool_cutter_profile` for those edits.
- `delete_tool { "name": string }`: Delete a document tool through the undoable `DeleteTool` (one undo step; undo restores its number, holder body and cutter). Refused by tool name, changing nothing: an unknown name, an entity that is not a tool, or a tool an operation still uses (`set_tool` the operation onto another tool first).
- `set_tool_number { "tool": string, "number": integer }`: Give a document tool its controller number (the `T..` / `H..` a post writes, matching the machine's tool table). Returns `number` and `posts_as`. One undo step. Refused by name: an unknown or non-tool name, a number outside 1-99999, `null`, a number another tool already has on the same machine, a no-op.
- `list_holder_library {}`: List the built-in holders (BT30/BT40/CAT40 with ER or Weldon, standalone ER chucks) with dimensions and the shanks each takes.
- `set_tool_holder { "tool": string, "library"?: string, "gauge_len"?: number, "projection"?: number, "points"?: [{z, r, arc?}], "clear"?: bool }`: Set a tool's holder from a library entry, a drawn spun profile, or back to the cylinder (exactly one of `library`/`points`/`clear`); one undo step. `get_job` shows it as each tool's `holder`. With `library` the tool stores a reference to the entry (#2016): `holder.library` is `{entry, gauge_len, projection}` and the outline in `holder.points` is drawn from the library; `points` sets a custom holder (`holder.library` is null), except that the referenced holder's own outline sent back unchanged keeps the reference.
- `set_tool { "operation": string, "tool": string }`: Assign a document tool to an operation.
- `get_tool_cutter_profile { "tool": string }`: Read a milling tool's cutter, neck and shank as a spun half-outline: points `[z, r, arc]` from the tip (z = 0, on the axis) up to the shank top (`arc` = 0 for a straight segment, else the signed radius of an arc to the next point). `drawn` says whether it is a hand-drawn outline or the one the tool's numbers draw. Turning tools have none.
- `set_tool_cutter_profile { "tool": string, "points": [[z, r] | [z, r, arc], ...] | null }`: Set a milling tool's drawn cutter outline (tip-up, closed to the axis at both ends), or clear it with `null` (back to the outline its numbers draw). The outline must agree with the tool's numbers (reach exactly the stated diameter within the flute length, end at flute + shank length, not exceed the cutter or shank width above the flutes, not fold over itself), else it is refused by name. Toolpaths keep reading the numbers; the collision checks and the simulation read a drawn neck where it is narrower than the stated shank (never wider). One undoable step.
- `set_work_material { "material": string | null }`: State the document's workpiece material (`aluminium_6061`, `mild_steel`, `stainless_304`, `grey_cast_iron`, `brass`, `plastics_pom`, `softwood`, `hardwood`, `mdf`, `plywood`, `acrylic`, `hdpe`), or `null` to clear it. Re-stating the current one or an unknown word is refused by name. One undoable step; `get_job` shows it as `work_material`.
- `set_stock_material { "material": string | null }`: State the active setup stock's workpiece material (same words as `set_work_material`), or `null` to clear it. Picks each tool's cutting-data row for that setup's operations in order (stock, then document, then the tool's `Unknown` row) and re-seeds their `feed` (rows naming the material) and `stepdown` / `stepover` in one undoable step (`SetStockMaterial`); tools' running `rpm` and `feed` follow the document material only. Returns `{ stock, stock_material, operations_seeded }`. Refused by name when the active setup has no stock, the stock already states that material, or the material word is unknown.
- `suggest_cutting_data { "operation": string }`: The feeds-and-speeds suggestion for the operation's tool on the stated material, as data (writes nothing): `material`, `tool_material`, `cutting_speed` m/min, `feed_per_tooth` mm, `thinning_factor`, `rpm`, `feed` mm/min, `machine_clamps`. Refused by name when no material is stated or the table cannot speak for the tool.
- `apply_cutting_data { "operation": string }`: Apply that suggestion: the operation's feed and its tool's rpm, one undoable step (the Cutting data page's Apply). Refused by name with no material, a kind with no milling feed, or an op already on the suggestion. Returns what was applied.
- `set_tool_cutter_params { "tool": string, "params"?: {diameter?, corner_r?, tip_angle?, flute_len?, shank_d?, shank_len?}, "neck"?: {diameter, length} | null }`: Edit a milling tool by the numbers its cutter outline is drawn from (mm; `tip_angle` in degrees; any subset, the others keep their value), and optionally its neck: `{diameter, length}` draws a straight neck up from the flute top, `null` drops the drawn outline (back to the outline its numbers draw), omitted keeps what is drawn. A drawn outline is carried onto the new numbers (tip regenerated from the kind, a drawn neck kept above the new flute top, shank top moved). Numbers and outline land as one undo step. Every tool-edit and cutter refusal is by name (a neck must sit below the shank's diameter and inside its length).
- `import_tool_library { "path": string, "mode"?: "add"|"update"|"replace", "holders"?: bool, "format"?: "auto"|"camtools"|"pathpilot"|"hurco", "units"?: "mm"|"inch" }`: Import tools from a `.camtools` library, Tormach PathPilot `.csv` tool table, or Hurco WinMax `.TCM` library as one undo step (#2566). `format` defaults to `auto` (detected from extension or content); `units` defaults to the document's units for controller tables (`.camtools` is always `mm`). `mode` (#899, default add) decides what a same-named document tool does: add skips an identical one and renames a different one, update takes the file's definition in place (operations go Stale), replace also removes tools the file lacks unless an operation uses one. `holders` (default true, #889) takes each tool's holder from a `.camtools` file. PathPilot `.csv` and Hurco `.TCM` imports also carry controller tool numbers (`T<n>`); unsupported Hurco `ToolType` codes, bad rows, or tool-number clashes refuse by name.
- `export_tool_library { "path": string, "format"?: "auto"|"camtools"|"pathpilot"|"hurco", "units"?: "mm"|"inch" }`: Export document tools to a `.camtools` library, PathPilot `.csv` tool table, or Hurco `.TCM` tool library.
- `get_tool_body { "tool": string }`: A tool's modelled body (#361), or `body: null` when it has none: a `"spindle"` body's axis, `tip_offset` and revolved envelope (`foot`, `top`, `max_radius`), or a `"lathe"` body's placement (`radial`, `along`, `tip`), `insert_zone` and `extent` from the tip, plus `"pieces"` (`[{ index, source, facets, csys }]`). Lengths in mm.
- `set_tool_body { "tool": string, "path": string, "axis"?: [x, y, z], "tip_offset"?: number }`: Give a milling tool a body from a holder or assembly file (STEP, STL, OBJ) along the spindle axis. With `axis` (model direction, tip toward spindle) and `tip_offset` (model origin's height above the tip): numeric placement. With neither: a STEP is aligned by the ISO 13399 tool coordinate systems it names, and refused by name when it names none. The collision laws then judge the body's revolved envelope. A lathe-held tool is refused (use `set_lathe_tool_body`).
- `set_lathe_tool_body { "tool": string, "path": string, "radial": [x, y, z], "along": [x, y, z], "tip"?: [x, y, z], "insert_zone"?: { "lo": [x, y, z], "hi": [x, y, z] } | null }`: Give a lathe-held tool (turning, grooving, threading, form insert, or a boring bar) a holder body in the turning tool frame: `radial` is the model direction away from the spindle axis, `along` the model direction of the lathe's +Z, `tip` the model point the moves carry, in mm in the model's frame after import (an inch or metre STEP is scaled to mm; STL and OBJ numbers are read as mm; default the model origin). The body need not be symmetric; every move of a turning operation is then judged against the part and the standing stock, and a rub blocks the post. `insert_zone` is the insert plate's box about the tip (turning frame), which the judge leaves out.
- `attach_tool_body_piece { "tool": string, "path": string, "target_piece"?: int, "target_csys"?: string, "piece_csys"?: string, "axis"?: [x,y,z], "tip_offset"?: number, "radial"?: [x,y,z], "along"?: [x,y,z], "tip"?: [x,y,z] }`: Attach a modular adapter, extension or clamping unit onto a tool's existing body (#361 / #1040), mating by unambiguous ISO 13399 `MCS` <-> `CSW` coordinate systems by default or explicit CSYS/placement arguments; judged and displayed as one body. One undoable step.
- `remove_tool_body_piece { "tool": string, "index": int }`: Remove one piece (0-based index) from a multi-piece tool body assembly and rebuild its collision envelope; refuses removing the only remaining piece (`clear_tool_body` removes the whole body). One undoable step.
- `set_lathe_insert_zone { "tool": string, "insert_zone": { "lo", "hi" } | null }`: Set or clear the insert zone of a tool's lathe body, keeping its mesh and placement.
- `clear_tool_body { "tool": string }`: Remove a tool's body (either frame); the holder cylinder is judged again, and a turning tool's holder goes unjudged (its operations say so).
- A body file too detailed to import at full fidelity (#864) is refused by name by every body tool: a coarse holder would read smaller than the holder is. Simplify the model and import again.
- **Thread-mill tools (#989)**: `add_tool { "catalog": "TM-0600-P125" }` adds a multi-form mill at 1.25 mm pitch; `add_tool { "catalog": "TMS-0600-P050-150" }` adds a single-form mill for 0.5 to 1.5 mm pitches. In a full `definition` (copy the shape from `get_job`), `kind` is `"thread_mill"` or `"thread_mill_single"`. `pitch` is the multi-form mill's fixed pitch or the single-form mill's maximum pitch; `pitch_min` is the single-form mill's positive minimum pitch (no greater than `pitch`; omit it for a multi-form mill). A single-form definition without the `pitch_min` key reads as a range of its one `pitch` (#3662); a stated 0 is refused. Lengths and pitches are in mm; `diameter` spans the tooth crests, `flute_len` is the cutting length, and `tip_angle` is the included form angle in degrees. Thread milling requires the 60-degree form. Use `list_tool_catalog` for the full catalog definitions.

### 5. Operations & Geometric Features (`tools.rs`, `pick.rs`, `area.rs`, `features.rs`, #180, #312)
- `list_operation_types {}`: Inspect all supported operation types, parameter schemas, defaults, and compatible tool types.
- `add_operation { "kind": string, "tool"?: string, "name"?: string, "source"?: string, "params"?: object }`: Add an operation to the active setup. `source` is `"stock"` (the default), a model name, or the name of a placed DXF profile (#1862: 2D milling, plasma and wire EDM kinds only; a kind that needs a solid model refuses a profile by name, and a 3D kind refuses a setup that has only a stock and a profile). `tool` is required for every kind where `list_operation_types` lists `"mounts_tool": true` (including `Wire Contour` with a `Wire` tool such as `"EDM-W025"`); only a kind with `"mounts_tool": false` omits `"tool"`.
- **Wire Contour (#532, #1108, #2011)**: a 2-axis, constant-taper, or 4-axis wire EDM cut of one closed profile (a model's through silhouette or picked edges) or an open run (`side: "left"|"right"`). Mount a wire EDM first: built-in `"Sodick ALC400G"` or `"AGIECUT Classic 2S (template)"` via `load_machine { "builtin": "..." }` (plus `edit_machine` to add `edm.conditions` and any `edm.codes`), or `load_machine { "path": "<.mch>" }` with an `edm.conditions` table. Add a `Wire` tool (`add_tool { "catalog": "EDM-W025", "holder": "none" }`, or a custom tool with `kind: "wire"`, `diameter` 0.02-1.0 mm, `rpm: 0`). Then `add_operation { "kind": "Wire Contour", "tool": "EDM-W025", "source": "<model>", "params": { "condition": "<condition id>", "side": "die"|"punch"|"left"|"right", "picks": { "start": [[x, y]] } } }`. All fields (`list_operation_types { "kind": "wire_contour" }`): `top_z`, `bottom_z`, `condition`, `side`, `picks`, `start`, `tabs`, `capture`, `both_pieces_restrained`, `stock_centered_in_xy_travel`, `taper_deg`, `burnout_clearance`, `clearance`, `skims`, `four_axis`, `sharp_corners`, `lead_arc_radius`; `edit_operation` patches any of them. `lead_arc_radius` (mm, absent or `null` = the straight lead, #3991) states a tangent arc lead-in and lead-out on a selected DXF chain's vertical single pass: it must be more than the kerf offset of the resolved condition (wire radius + spark gap; refused at the command door, and again at `generate` for a loaded file), the start hole must stand more than twice the radius off the path, and a lead nearer the profile than the kerf offset is refused by name; beside an open run, tabs, skims, a taper, a burnout, a 4-axis cut or an exit pick it is refused at the command door. Refusals arrive as tool errors in the command's words: missing or non-wire tool, no or unknown condition, a condition with no gap or wire diameter, or `taper_deg` past `edm.max_taper_deg`; the start hole and the corner minimum are refused at `generate`. Post with `"Generic ISO Wire EDM"` (vertical, skims, constant taper, and 4-axis via `edm.codes`), `"Sodick Wire EDM (Mark 21)"` (vertical 2-axis only; refuses taper and 4-axis), or `"Agie Wire EDM (AgieVision)"` (an AgieVision job directory of ISO, SBR and SBL files for `"AGIECUT Classic 2S (template)"` with condition `AGIE_QN2`, one straight-sided vertical punch (`source: "<model>"`, `side: "punch"`) in 15, 20, 40 or 80 mm stock, or one convex die opening (`side: "die"`, the picked edge chains of the upper rim through `set_operation_geometry`) in a 20 mm plate, or one straight open cutoff (`side: "left"|"right"`, one picked X- or Y-parallel wall edge across the 20 mm stock, no `start`, `both_pieces_restrained` and `stock_centered_in_xy_travel` true, `clearance` at most 3.6, option `separationLengthMm: 0`), and 0.25 mm wire; punch reentrant corners are checked, not refused: each inside corner must be reached by the rough offset of the selected thickness within 0.002 mm, every segment must hold both corner joins, nonadjacent faces must keep the swept rough passes apart, and the entry must be on a straight exterior face; a notch that fails these checks is refused, see `docs/decisions/2956-agie-reentrant-punch.md` and `docs/user-guide/agie-wire-edm.md`); milling posts refuse wire cuts by name. Neither built-in wire `.mch` ships with `edm.conditions`, and the wire posts are not exercised on a physical EDM control.
- **Sinker electrode (#547, #1156)**: `electrode_from_faces { "name": string, "picks": [face ids], "undersize"?: number, "condition"?: string, "setup"?: string, "orbit"?: number, "stub": number, "pickup": number }` generates a sinker EDM electrode from the picked faces of a cavity (its level floor and every vertical wall standing on it, `face:0x…` ids from `list_features`, all on one model) and adds it as a document tool. Give `undersize` (mm per side, 0 or more) or `condition` (a machine EDM condition id, read from the setup's sinker EDM; `setup` names that setup, default the active one), not both; `stub` (more than 0) is how far the electrode stands above the cavity's mouth; `pickup` (0 or more) is the offset from the electrode's top to the measuring reference. `orbit` makes it that much smaller again per side. The reply gives the electrode, its `burn` fields (the `add_operation` params of a Sinker Burn of this cavity) a `warning` when the stated undersize is 0 (the electrode is then the cavity's full size, so any spark gap burns the walls past it), and a `note` when an orbit is given. Only an axis-aligned rectangular cavity yields an electrode; refused by name: picks on more than one model or on something that is not a face, a degenerate face, a boss, rib or overhang standing in the electrode's way, a condition with no undersize or no sinker EDM setup, a model whose facets can't be read, and malformed numbers. One undo step.
- `edit_operation { "name": string, "params": object }`: JSON merge-patch operation parameters (e.g. `stepdown`, `stepover`, `feed`, `spindle_speed`).
- **Change a lead shape (#2876)**: `add_operation` and `edit_operation` merge object keys, including enum shape keys. Inspect the current shape with `get_job`, or the seeded defaults with `list_operation_types`. To change a linear lead to an arc, give `"params": { "lead": { "linear": null, "arc": { "radius": 3.0 } } }`. Remove the old key with `null` in the same patch. For a nested lead, give `"params": { "links": { "approach": { "lead_out": { "linear": null, "arc": { "radius": 3.0 } } } } }`. - **Pass starts at (#3316)**: `edit_operation { "name": "O1", "params": { "pass_start": "outside" } }` sets where each level's rings start on a 2D Offset: `"auto"` (the default, the core first; the reply leaves the key out), `"inside"` (the part or island wall first) or `"outside"` (the outer edge first; with an Outside containment the stock edge, so each level starts in air). Inside and Outside cut rings that follow the start edge one stepover at a time; where the first ring runs along a wall, or the area is narrower than the tool plus one stepover, a cut takes the full tool width and the toolpath carries a `Pass start` note (a warning line on the op page). Any other word is refused. One undo step. The same key is on 2D Pocket, 2D Adaptive, Circular, Bore, 3D Pocket and 3D Finish (#3354, #3355, #3359, #3360, #3361, #3362), through the same `edit_operation` door. Absent means `"auto"`. The project file does not write `"auto"`, and the reply leaves it out. Where the choice is not used, the app says so: 2D Pocket with Zigzag rows or with rest machining, and 3D Pocket with the Zigzag or Auto strategy, with rest machining, or with the Adaptive (HSM) strategy, carry a `Pass starts at` note and cut in the Auto order. Face, Slot and Trochoidal Slot refuse the key by name (no inside or outside order). Any other kind refuses it as an unknown field.

The default is 2.0 mm; the project file and the reply leave the key out at the default. Zero is legal; a negative or non-finite value is refused by name on creation and edit. One undo step. The Lead in / Lead out page shows it as "Approach distance" on 2D Offset, 2D Pocket and 2D Adaptive when Pass starts at is Inside or Outside. - **Threading infeed (#1847)**: `get_thread_infeed { "name": string }` reads a Threading operation by key or display label. `set_thread_infeed { "name": string, "infeed_plan": { /* partial fields */ } }` changes its plan. - **Thread milling (#989)**: Use `add_operation { "kind": "Thread", "tool": "TMS-0600-P050-150", "params": { "pitch": 1.0, "hand": "left" } }`; `edit_operation` patches the same `pitch` and `hand` keys in `params`. `hand` is `"right"` (default) or `"left"`. `pitch` is a positive finite number in mm, or `null` to leave it unstated: a multi-form mill defaults to its own pitch and refuses a different pitch; a single-form mill requires a stated pitch inside its `pitch_min` to `pitch` range. An unstated single-form pitch leaves an unfinished operation that `generate` refuses by name. Thread requires a thread mill; a Tap is refused. A form other than 60 degrees and an out-of-range pitch are refused on creation, edit or tool change. For internal threads, each `holes` entry's `radius` is the thread's minor radius (the drilled hole), and the mill must be smaller than that hole's minor diameter. For `external: true`, `detect_holes` selects bosses instead, whose radii describe their major cylinders.

- **Through-hole break-through (#1557, #2441)**: `add_operation` and `edit_operation` take `"break_through"` in `params` for Drill, Bore and Thread: how far past a through hole's floor the cut runs, in mm. `null` is the default and means the kind's own 1.0 mm; the reply leaves the key out until it is stated. A negative or non-finite value is refused on creation and edit. Drill also takes `"break_through_from"`, the Holes page's "Break-through from": `"full_diameter"` ("Full diameter", the default) adds the drill point length, so the full diameter clears the hole; `"tip"` ("Tip", the behaviour of project files before v68) stops the drill tip at the floor minus `break_through`. Any other value is refused. Example: `edit_operation { "name": "Drill1", "params": { "break_through": 0.5, "break_through_from": "tip" } }`. `list_operation_types` lists `break_through` (`number`, default `null`) for drill, bore and thread, and `break_through_from` (`string`, default `"full_diameter"`) for drill. A spot cycle stops above the through floor, so no break-through applies. At `generate` the path's notes say how far the holes run past the part bottom; an exit into a modelled fixture under the stock is a fixture hit that holds the post. A lathe's axial and cross holes refuse a stated break-through by name.
- `set_operation_coolant { "name": string, "coolant": "off" | "flood" | "mist" | "air" | "through-tool" }` (`coolant_tools.rs`, #974): Set coolant by operation key or display label through `EditOperationParams::with_coolant`. One undo step; the cached toolpath stays valid. The reply gives `operation` and `coolant`. Repeating the current mode is accepted.
- **2D Pocket rest machining (#1489)**: `edit_operation { "name": "<pocket>", "params": { "rest": { "previous_tool_diameter": 12, "previous_corner_radius"?: 0, "previous_stock_to_leave"?: 0, "allowance"?: 0 } } }` makes the Pocket cut only what the larger previous tool (entered by hand, in mm) could not reach; `"rest": null` turns it off (off is the default, and a file without the key reads as off). At `generate`: "no rest material" when the previous tool reached everything.
- **2D Adaptive rest machining (#1446)**: `edit_operation { "name": "<2D Adaptive>", "params": { "rest": { "source": "previous_operations", "allowance"?: 0 } } }` makes the 2D Adaptive cut only what the earlier operations of the same setup left. The stock that they leave is read at every cut depth, and each plunge stands where that stock proves the whole cutter clear. `"rest": null` turns it off (off is the default). One undo step; kept in the project file. Generate the earlier operations first. Refused by name at the edit: `source` absent or `entered_tool` (an entered tool proves nothing here; use a 2D Pocket for that mode), a negative or non-finite `allowance`, the Trochoidal method, arc turns, a tilt. Refused by name at `generate`: an earlier operation with no toolpath, a stale toolpath or a suppressed cut; no cut ahead to enter from; a roughing pass that stops above the floor of this operation (no entry with proved clearance); "no rest material".
- `delete_operation { "name": string }`: Remove an operation and invalidate its cached toolpath.
- `rename_operation { "name": string, "new_name": string }`: Change an operation's display name (1-120 printable characters). Its stable key and its place in the program do not change; naming it back to its key clears the display name. Names are unique and cannot take another operation's key. One undo step.
- `reorder_operation { "name": string, "target": string, "place"?: "before" | "after" }`: Move an operation before (default) or after another operation of the SAME setup, as the browser's drag and drop does. Moving between setups is refused. Answers with that setup's operations in their new order. One undo step.
- `mark_operation_reviewed { "name": string }`: Clear a migrated operation's `needs_review` flag once inspected (#1517; un-carriable pre-v69 fields such as `rest` or `predrilled` block posting until reviewed). One undo step.
- `list_features { "model": string }`: Query pickable faces, loops, edge chains, and vertices with stable IDs on models/fixtures, or `sketch_chain:<hex>` chains and `sketch_layer:<layer>` layers on placed DXF profiles (#1864). A face row gives the outward `normal` and `facing`; when the shell is open or inside-out they are null and `outside_unknown` names why (#2186), as `lay_part_on_face` refuses it.
- `get_operation_geometry { "operation": string }`: Inspect the features, per-chain overrides, and area boundaries an operation machines.
- `set_operation_geometry { "operation": string, "picks": [{ "model", "id", "side"?, "reverse"? }, ...] }`: Bind specific geometric feature IDs to an operation. For `2D Contour` on DXF profiles, `sketch_chain` picks may also set optional `"side"` (`"inside"` | `"outside"` | `null`) and `"reverse"` (`boolean`) per-chain overrides (#1864).
- `pick_in_box { "operation": string, "box": { "x0", "y0", "x1", "y1" }, "mode"?: "window" | "crossing", "kind"?: "chains" | "faces", "replace"?: bool, "through"?: bool }`: The viewport's box select headless (#979): seen from straight above (+Z, like the Top view), adds every feature edge chain (default) or face whose outline lies inside the world X/Y box (`window`, default) or touches it (`crossing`) to the operation's picks; `replace: true` replaces them. Without `through` (default false) the box is visible-only - hidden edges and faces under the top face stay out; `through: true` takes them too, like the Pick through toggle. Mesh triangulation edges are never taken. One undo step. Refused by name: a box with no area, a non-finite corner, a box that holds nothing new.
- `set_operation_area { "operation": string, "area": { "containment"?, "offset"?, "corner"?, "extension"?, "extra"?, "open"? } }`: Configure the area controls (containment `"inside"` | `"outside"` | `"center"`, offset, corner, ...); omitted fields take their defaults.
- `get_operation_do_not_touch { "operation": string }`: Read protected `"Do not touch"` faces/edges and clearance (mm).
- `set_operation_do_not_touch { "operation": string, "clearance"?: number, "picks"?: [{ "model": string, "id": string }] }`: Set protected faces/edges and standoff clearance (mm; `stock_to_leave` still adds on top) on `2D Contour`, `2D Offset` and `3D Pocket` operations so no move (flutes, shank, holder) can approach within that clearance. Refuses unsupported operation kinds, vertex picks, and overlap with the machining selection or Include boundary. One undo step.
- `detect_holes { "name": string }`: Automatically detect and populate hole coordinates for Drill, Bore, or Thread operations from the source model (a Thread operation with `external: true` gets upright round bosses instead; Drill on a lathe or mill-turn also fills radial cross holes). Returns `{ operation, holes, radial_holes, skipped, status }`. A Bore operation clears wide holes with concentric rings (#1566). Holes whose plan needs more than 4096 rings, or whose floor band is zero or too small (for example, a ball cutter at a flat blind floor), are left out and named (one sentence each) in `skipped`. If every detected hole is skipped for a Bore operation, `detect_holes` is refused by name (`no hole this Bore op can make: ...`) and stores nothing. One undo step.
- `detect_pockets { "model": string, "create"?: integer, "tool"?: string, "name"?: string }`: A model's recognised pockets and slots (closed or open pockets, straight slots with open, round or square ends): boundary, floor and top Z, depth, tightest inside corner, slot width and open sides. With `create` (the index of a listed feature) it adds the Pocket, or a Slot for a round or open-ended slot, that machines it, with its area and depths taken from the feature; `tool` is then required and `name` defaults to Pocket1, Slot1, and so on. One undo step.
- `set_part_axes { "y"?: picks, "x"?: picks, "flip_y"?: boolean, "flip_x"?: boolean, "primary"?: "y" | "x", "setup"?: string }`: Align the part from picked axes, as the Setups page's "Part axes" rows do (`AlignPartToSetup::align_from_axes`). Picks are `list_features` ids: one edge chain, or two points (first to second) - a point is a vertex id, or (#692) the chain id of a circular edge (a hole rim, a boss edge), read as its centre through the same picking service the GUI's centre snap uses; `flip_y` and `flip_x` reverse a pick. One axis: the part turns in the work plane so the pick runs along it (`frame: "in_plane"`, `turn_deg` reported). Both axes (#1329): their 3D directions define the full frame (`frame: "full_3d"`, `turn_deg` null) - `primary` (default `"y"`) lands exactly, the other is made square to it, and +Z lands on the right-hand cross of the picks, so a vertical edge as +Y lays the part on its side and a left-handed pair is honoured literally (the part lands on its head), not refused. Turns about the part's bounds centre, composed onto the setup's current part alignment; the work offset is untouched; one undo step. Refused by name: a face, a curved edge as the one pick, an edge in a point pair that is not circular (straight, or no circle within tolerance), coincident points, a single pick along Z, X and Y picks running (nearly) along each other.
- `align_part_cylinder { "pick": { "model": string, "id": string }, "setup"?: string, "target"?: "x" | "y" | "z", "angle_deg"?: number, "flip"?: boolean }` (#1586): Align the part from one picked cylinder wall (`list_features` patch id) through `AlignPartToSetup::align_from_cylinder`, as the Setups page does. The cylinder axis lands on `target` (default `"z"`); `angle_deg` (default 0) turns about that axis and `flip` (default false) reverses it. Defaults to the active setup. Returns the setup, stored alignment and its description. One undo step. Refuses unknown models or setups, a pick that is not a cylinder wall, a non-finite angle, an axis that cannot land on the target, and an unchanged alignment by name.
- `place_setup_origin { "source": "model_box" | "stock_box" | "vertex", "setup"?: string, "point"?: "corner" | "centre", "pick"?: { "model": string, "id": string } }` (#1586): Place a setup's WCS origin from the parts' bounds, that setup's stock bounds, or a picked vertex, keeping its current rotation. Defaults to the active setup. Box sources use `point` (default `"corner"`) and reject `pick`; the vertex source requires `pick` and rejects `point`. Resolves through `place_setup_origin` and executes `SetWcsOrigin::for_setup`, as the Setups page does. Returns the setup, origin and rotation. One undo step. Refuses missing models or stock, unknown models or setups, an invalid vertex pick, and an unchanged origin by name.
- `lay_part_on_points { "points": [id, id, id], "setup"?: string, "plane"?: "g17" | "g18" | "g19", "flip"?: boolean, "place"?: boolean, "frame"?: boolean }`: Lay the part on a setup's G17 (XY), G18 (ZX) or G19 (YZ) plane through three picked points (`list_features` ids, exactly three): vertex ids, or (#692) circular edge chain ids, each read as its circle's centre (a straight or non-circular edge is refused by name). The plane through them is turned so its outside, the side away from the part's material, faces the plane's axis (`flip` reverses it, so on G17 the points rest on the table). `place` (default true) sets point 1 onto the plane's level. `frame` (3-2-1) also turns point 1 to 2 along +X (+Y for G19) and moves point 1 to the setup origin. One undo step.
- `lay_part_on_face { "face": {model, id}, "setup"?: string, "plane"?: "g17" | "g18" | "g19", "flip"?: boolean, "place"?: boolean }` (#729): Lay the part on a setup's G17 (XY), G18 (ZX) or G19 (YZ) plane by one picked flat face (a `list_features` face id as `{model, id}`), as the Setups page's "Lay on a plane" face pick does (`AlignPartToSetup::lay_on_plane`). The face's outward normal is turned to face the plane's axis (`flip` reverses it, so on G17 the face rests on the table) and, with `place` (default true), its centroid is set onto the plane's level. Returns `setup`, `outside`, the stored `alignment` and its `description`. One undo step. Refused by name: an edge, a vertex, a curved or degenerate face, more than one face, a fixture or pick off the part, a lay the setup already holds.

### 6. Generation, Simulation & Posting (`tools.rs`, `job.rs`, `render.rs`, #182)
- `generate { "name"?: string }`: Generate toolpaths for a named operation or all stale operations. Returns an array of operation rows. Each operation row can include `notes`, an array of strings, omitted when empty. These informational notes describe generation limits such as uncut bands or corners; unlike blocking warnings, they do not block posting.
- `verify { "name"?: string }`: Check toolpaths against safety rules (spindle speed, rapids touching material, shaft collision, machine limits). Returns operation rows in `operations`, with cached `warnings` and optional per-operation `notes`, an array of strings, omitted when empty. These informational notes do not block posting; inspect `ok`, `held_by` and `gate` for the safety verdict.
- `render_stock { "width"?: number, "height"?: number, "view"?: "iso" | "top" }`: Render simulated stock to a PNG image with rest/gouge color shading.
- `get_post_options { "setup"?: string | null }`: Read post options (`skip_stops`, `per_op`, `threading`, `end_units`, `smoothing`, `between_setups`, `wcs_rotation`, `explain`), `follows_document`, `own`, `post`, `script_schema`, and resolved `script_options`. With `setup`, reads that declared setup's resolved options; without `setup` (or `null`), reads the document's (#1534, #258).
- `set_post_options { "setup"?: string | null, "follow"?: boolean, "skip_stops"?: boolean, "per_op"?: boolean, "threading"?: "g32"|"g76", "end_units"?: "leave"|"inch"|"mm", "smoothing"?: boolean, "between_setups"?: "pause"|"optional-stop"|"continue"|"file-per-setup", "wcs_rotation"?: "bake"|"control", "explain"?: boolean, "script_options"?: object }`: Set post options and/or per-post `script_options` (pass `null` on a key to reset it to the script default) as one undoable step (#1534, #258). Target is explicit (no implicit active-setup routing): with `setup`, writes that setup's own options, or `follow: true` returns both built-in and script options to following the document; without `setup`, writes the document's. Omitted fields keep their current values; no-ops and unknown setups/values/options are refused by name.
- `post { "output": string, "post"?: string, "between_setups"?: "pause"|"optional-stop"|"continue"|"file-per-setup" }`: Post-process verified toolpaths into the NC file `output` through a built-in post by name (`"Fanuc"`, `"Haas"`, ...) or a `.cps` path. `between_setups` (#1532) first sets what the program does where it changes setup, as an undoable command: `pause` (the default) writes M0 with a comment naming the next setup, `optional-stop` M1, `continue` runs straight on, and `file-per-setup` writes one program per setup beside `output` (the reply's `files` names them).

## Waterjet Profile workflow (#1883)

This workflow requires the Waterjet Profile implementation in #1883 (PR #3058).
That implementation is not yet on `main`.
There is no built-in waterjet. Mount a `.mch` file whose machine `kind` is
`"waterjet"` with `load_machine { "path": "waterjet.mch" }`.
Add a nozzle with `kind: "waterjet"` and `rpm: 0`. Its diameter is the kerf width.

For a plate model spanning Z = 0 to 5 mm, call these MCP tools in order.
Use the actual machine file and plate model. Adapt the heights, leads, tab
positions and cutting parameters to the part and machine.

```text
load_machine { "path": "waterjet.mch" }
add_tool { "name": "Nozzle", "definition": { "kind": "waterjet", "diameter": 0.8, "corner_r": 0, "tip_angle": 0, "pitch": 0, "nose_radius": 0, "width": 0, "flute_len": 10, "shank_d": 30, "shank_len": 100, "holder_d": 0, "holder_len": 0, "material_group": "mild steel", "rpm": 0, "feed": 2500, "center_cutting": false } }
import_model { "path": "plate.stl", "name": "plate" }
add_operation { "kind": "Waterjet Profile", "name": "Jet1", "tool": "Nozzle", "source": "plate", "params": { "clearance_z": 25, "top_z": 5, "bottom_z": 0, "kerf": null, "control_comp": false, "reversed": false, "lead": "arc", "lead_in": 4, "lead_out": 3, "open_side": "center", "tabs": { "count": 1, "width": 2, "at": [[20, 0]] }, "feed": 250, "pierce_time": 2.5, "abrasive_delay": 0.5, "linearize": 0.01 } }
generate { "name": "Jet1" }
```

Use `list_operation_types` for the complete parameter fields and defaults.
`kerf: null` uses the nozzle diameter. `control_comp` selects controller
compensation; `false` uses computer compensation. `reversed` reverses the cut.
`lead` accepts `arc` or `straight`; `lead_in` and `lead_out` set their lengths.
`open_side` accepts `center`, `left` or `right` for an open chain.
`tabs` supplies `count`, `width` and explicit XY positions in `at`.
Lengths and the optional `linearize` tolerance are in mm; `feed` is in mm/min.
`linearize: null` keeps arcs.

`pierce_time` and `abrasive_delay` are in seconds. They appear in path notes
only until #1882 adds post support. Inspect the notes returned by `generate`.
No post serves a waterjet yet. Do not use a milling or plasma post for this path.
The implementation in #1883 pins this workflow in
`crates/app/tests/mcp_waterjet.rs`. Those tests run headlessly, not on a machine.

## Plasma Profile workflow (#1871)

The built-in `Tormach 1300PL` uses a `Torch` tool and the `Tormach PathPilot Plasma` post. The catalog tool `PT-KERF-150` has a 1.5 mm kerf and zero rpm. For a plate model spanning Z = 0 to 5 mm, call these MCP tools in order (arguments shown below):

```text
load_machine { "builtin": "Tormach 1300PL" }
add_tool { "catalog": "PT-KERF-150" }
import_model { "path": "plate.stl", "name": "plate" }
add_operation { "kind": "Plasma Profile", "name": "Plasma1", "tool": "PT-KERF-150", "source": "plate", "params": { "clearance_z": 25, "top_z": 5, "bottom_z": 0, "lead_in": 4, "lead_out": 3, "overburn": 1 } }
edit_operation { "name": "Plasma1", "params": { "pierce_delay": 0.5 } }
undo {}
redo {}
generate { "name": "Plasma1" }
verify {}
```

The edit, undo and redo above set, remove and restore the pierce delay. Adapt the heights and leads to the actual plate. Use `list_operation_types` for the complete parameter fields and defaults. `kerf: null` uses the torch's diameter; `comp` is `"computer"` (default) or `"control"`. Optional `feed` (mm/min), `pierce_height` and `cut_height` (mm above the plate), and `pierce_delay` (seconds) leave the controller's AutoFS in charge when unset; an `edit_operation` patch with `null` clears one.

Inspect `verify`'s `ok`, `gate.problems`, and `gate.not_judged`. The latter says that the 3D stock simulation does not run for plasma and reports the 2D plasma laws instead: cut order, cut crossing, kerf crossing and tip-up. Cut-order and cut-crossing failures block posting; kerf-crossing and tip-up warnings remain visible in that line. A clean report does not mean that a 3D stock simulation ran.

After verification, post with the explicit plasma post:

```text
post { "output": "plate.nc", "post": "Tormach PathPilot Plasma" }
```

This `post` argument applies to this call; it does not change the stored post selection. For a declared setup, `set_setup_post` can store the plasma post for later calls that omit `post`.

Refusals return `isError: true` with a named reason. Assigning an end mill with `set_tool` is refused because Plasma Profile requires a plasma torch. `edit_tool { "name": "PT-KERF-150", "patch": { "rpm": 3000 } }` is refused because a torch turns no spindle. A milling post such as `Fanuc` refuses the plasma machine. A cached path that cuts an outline before its hole produces a `plasma cut order` problem in `verify` and blocks `post`; a refused post writes no NC file. These cases are pinned by `crates/app/tests/mcp_plasma.rs`. The tests run headlessly, not on a physical plasma table.
